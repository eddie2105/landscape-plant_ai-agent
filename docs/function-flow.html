app.py 原始碼順序講解：第 1 行到最後一行

這一段完全照 `app.py` 的原始碼順序讀，不重新分類。Python 會先執行最上面的 import 和全域設定，遇到 def 時只「登記函式」，直到最後 `if __name__ == "__main__"` 才真正呼叫 `render_app()` 啟動畫面。

第 1-10 行：imports，先準備整個 app 會用到的工具

`json` 給 `parse_ai_json()` 解析模型回傳；`os` 給設定與 proxy；`escape` 給 HTML 安全輸出；`altair` 畫圖；`gspread` 讀 Google Sheets；`pandas` 處理 DataFrame；`streamlit` 產生 UI；`load_dotenv` 讀 `.env`；`OpenAI` 呼叫模型。

為什麼這樣寫：import 必須放最上面，讓後面的常數和 def 都能直接使用這些工具。

連到哪裡：`json` 連到 `parse_ai_json()`；`gspread` 連到 `load_google_sheet()`；`OpenAI` 連到 `ask_ai()`；`st` 連到 `render_app()`。

第 13-33 行：proxy 防護，先清掉會阻擋外部 API 的壞設定

先定義 `DEAD_LOCAL_PROXY` 與 `PROXY_ENV_VARS`，再定義 `disable_dead_local_proxy()`。第 33 行立刻執行它，因為後面 Google Sheets 和 OpenAI 都需要正常連線。

為什麼這樣寫：這段要在任何 API client 建立前先執行，避免後面連線全部被壞 proxy 卡住。

連到哪裡：保護 `load_google_sheet()` 和 `ask_ai()` 的外部網路請求。

第 36-60 行：環境變數與月份契約

`REQUIRED_ENV_VARS` 告訴 app 哪些 `.env` 設定一定要有；`MONTHS` 把資料欄位的英文月份 key 對到畫面上的 1-12 月。後面的設定檢查、季節矩陣、覆蓋分析都會依賴它。

為什麼這樣寫：把必要設定和月份對照集中在前面，後面函式就不必各自硬寫一份規則。

連到哪裡：`REQUIRED_ENV_VARS` 連到 `find_missing_settings()`；`MONTHS` 連到 `build_seasonal_matrix()`、`build_coverage_analysis()`、`coverage_line_chart()`。

第 62 行：FINAL_REMINDER，先定義 AI 回答最後要提醒的話

這句會被塞進 `SYSTEM_PROMPT`，確保 AI 回答時提醒使用者實際配置仍要看基地條件。

為什麼這樣寫：提醒語只定義一次，prompt 多處引用時不會不一致。

連到哪裡：被第 64-111 行的 `SYSTEM_PROMPT` 插入使用。

第 64-111 行：SYSTEM_PROMPT，規定 AI 要怎麼回答

這是整個 AI agent 的回答規格。它要求模型只回 JSON，`answer` 放給人看的文字，`plant_ids` 放真正關聯到 Google Sheet 的植物 ID。後面 `ask_ai()` 會送出這段，`parse_ai_json()` 會照這個格式解析。

為什麼這樣寫：先把 AI 輸出格式講死，後面的程式才能穩定解析，不會每次回來都長不一樣。

連到哪裡：`ask_ai()` 負責送出 prompt；`parse_ai_json()` 負責接住 prompt 要求的 JSON。

第 113-130 行：顯示欄位與範例問題

`RELATED_PLANT_COLUMNS` 決定推薦植物表格要露出哪些欄；`EXAMPLE_QUESTIONS` 是左側快速提問按鈕。它們本身不執行流程，但會被 `render_app()` 拿來組畫面。

為什麼這樣寫：把畫面會用到的欄位和範例集中管理，避免 UI 區塊裡散落太多固定資料。

連到哪裡：都在 `render_app()` 裡被使用。

第 132-273 行：DASHBOARD_CSS，先把整個 Streamlit 視覺風格寫好

這一大段是森林色系、卡片、metric、按鈕、DataFrame 的 CSS。它先被定義成字串，等到 `inject_dashboard_css()` 被 `render_app()` 呼叫時才真正注入畫面。

為什麼這樣寫：Streamlit 的客製樣式需要透過 HTML/CSS 注入，所以先把樣式收成一個大字串。

連到哪裡：`inject_dashboard_css()` 讀它，`render_app()` 呼叫 `inject_dashboard_css()`。

第 275-298 行：UI 小函式，處理 CSS、卡片、指標與區塊標題

這裡開始進入 def。Python 讀到 def 時先登記，不會馬上執行。這幾個函式都服務 `render_app()`，讓畫面組裝可以重複使用。

為什麼這樣寫：把重複的 HTML 卡片和標題抽成函式，`render_app()` 才不會每次都手寫一大段 HTML。

連到哪裡：全部由 `render_app()` 在畫面組裝時呼叫。

第 301-327 行：設定與 Google Sheets 讀取

`load_settings()` 讀 `.env`；`load_google_sheet()` 用 service account 打開指定 worksheet，轉成 DataFrame，並保留 `plant_id` 的前導 0。這是資料進入 app 的入口。

為什麼這樣寫：先把設定讀取和 Sheet 讀取分開，出錯時比較知道是 `.env` 問題還是 Google Sheets 問題。

連到哪裡：`render_app()` 先呼叫 `load_settings()`，再呼叫兩次 `load_google_sheet()` 讀 plants 和 display_matrix。

第 330-394 行：把資料送進 AI，再把 AI 回答收回來

`build_context()` 把兩張表變 CSV 文字；`parse_ai_json()` 把模型回答整理成固定 dict；`ask_ai()` 把 prompt、問題、context 送給 OpenAI，最後回傳解析後的結果。

為什麼這樣寫：AI 需要文字 context 才能回答，而程式需要結構化 JSON 才能繼續做推薦表格和圖表。

連到哪裡：`render_app()` 呼叫 `build_context()`，再呼叫 `ask_ai()`；`ask_ai()` 內部再呼叫 `parse_ai_json()`。

第 397-468 行：設定檢查、文字正規化、植物比對與季節符號

這一段是資料清理層：檢查缺少哪些設定、把值轉成文字、根據 AI 的答案或 plant_ids 找植物、隱藏內部 ID、把 Google Sheets 的 1/0/true/false 轉成季節符號。

為什麼這樣寫：Google Sheets 和 AI 回傳都可能有空值、數字、字串混用，所以先用小函式統一資料格式。

連到哪裡：`render_app()` 會呼叫 `find_missing_settings()`、`find_related_plants_by_ids()`、`hide_internal_id_columns()`；季節相關函式會被 `build_seasonal_matrix()` 使用。

第 471-603 行：推薦結果的矩陣、統計圖與摘要

`build_seasonal_matrix()` 產生 12 個月觀賞矩陣；`build_coverage_analysis()` 算每月開花與葉色覆蓋量；`coverage_line_chart()` 畫 Altair 折線圖；`build_recommendation_summary()` 做 dashboard 指標摘要。

為什麼這樣寫：AI 只負責推薦植物 ID，視覺化和統計要由本地資料重新計算，結果才可控、可測試。

連到哪裡：`render_app()` 在拿到 related plants 後呼叫這一組函式，產生右側分析畫面。

第 606-787 行：render_app()，真正把所有前面定義的東西串起來

這是主流程。它設定 Streamlit 頁面、注入 CSS、讀設定、檢查缺漏、讀兩張 Google Sheet、畫 metric、建立輸入區、按下按鈕後建立 context、問 AI、解析 plant_ids、顯示推薦植物、摘要、折線圖和季節矩陣。

為什麼這樣寫：前面所有常數和小函式都先準備好，主流程最後才負責按照使用者操作把它們串起來。

連到哪裡：幾乎所有 `app.py` 的 helper 都被它直接或間接使用，是整個 app 的中心。

第 789-790 行：main guard，最後才決定要不要啟動 app

如果直接執行 `app.py`，這裡會呼叫 `render_app()`。如果測試只是 import `app.py`，這裡不會啟動 Streamlit，所以測試可以安全地拿函式來測。

為什麼這樣寫：讓同一個檔案可以被直接執行，也可以被測試 import，而不會一 import 就開 UI。

連到哪裡：直接連到 `render_app()`。

測試連結區

tests/test_app_core.py

保護 `app.py` 的核心資料處理：HTML escape、環境變數缺漏、AI JSON 解析、植物 ID 對應、季節矩陣、覆蓋分析、推薦摘要，以及 `ask_ai()` 能把 OpenAI 回傳轉成一致格式。

tests/test_connection_checks.py

保護 `connection_checks.py` 的設定讀取、API key 不外洩、Google Sheets 兩張 worksheet 抽樣讀取，以及 OpenAI models list 檢查。

偏 UI 的流程

`render_app()`、`inject_dashboard_css()` 和 Streamlit 版面組裝主要靠整合行為支撐；單元測試集中在它們呼叫的純函式，讓資料處理邏輯可以穩定回歸測試。
